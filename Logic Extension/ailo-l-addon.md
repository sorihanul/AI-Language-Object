"content": "# AILO-L v0.1 — Minimal Logic/Proof Add-on for AILO (Final)\n\n## 0) Purpose\nAILO-L is a lightweight **logic and proof plugin** designed to extend AILO when — and only when — formal reasoning, proof, or model checking is required. It remains fully **non-intrusive**, **deterministic**, and **resource-bounded**, preserving the simplicity of AILO while adding optional mathematical backbone.\n\n---\n\n## 1) Delta from Core AILO\n- **New Slots:** `thm, hyp, claim, form, goal, proof, oblg, model, badge, metric, assume`\n- **New Verbs:** `assert, assume, model, derive, prove` (existing `check` now accepts `goal`)\n- **Badge States:** `unverified | proved | falsified | unknown`\n- **Activation Flag:** `profile.logic = true` — plugin active only when set.\n\n---\n\n## 2) Slot Definitions (Minimal Required Subset)\n| Slot | Type | Description | Required |\n|------|------|-------------|-----------|\n| `claim` | string | Natural-language statement or theorem | Recommended |\n| `goal` | string | Target expression or logical goal | Required for `prove` |\n| `thm` | string | Theorem identifier | Optional |\n| `hyp` | array | Assumptions / premises | Optional |\n| `form` | string | Formal expression (λ / logic / Coq-style) | Optional |\n| `model` | object | Domain model or axioms | Optional |\n| `proof` | string | Proof sketch or strategy | Optional |\n| `oblg` | array | Proof obligations | Output only |\n| `badge` | enum | Verification state | Output only |\n| `metric` | object | {time, steps, conf, srm?} | Output only |\n| `assume` | array | Local temporary assumptions | Optional |\n\n> **Minimal usable trio:** `assert{claim}.`, `prove{goal}?`, `model{...}.`\n\n---\n\n## 3) Verb Signatures\n`\nassert(claim|form, hyp?) -> {badge, ref} sidefx:log\nassume(hyp[]) -> ok sidefx:context\nmodel(defs|axioms) -> ok sidefx:state(log)\nderive(hyp, rule?) -> {conclusion} sidefx:none\nprove(goal, model?, hyp?, with?, limit?) -> {badge, conf, trace, oblg?, counterexample?} sidefx:compute\n`\n\n`prove` accepts both `?` (trial/report) and `!` (commit). The `!` mode enforces AILO safety rules — must include `{rule|risk|conf}`.\n\n---\n\n## 4) Execution Semantics\n### 4.1 Badge Transitions\n- Default: `unverified`\n- Proof success → `proved`\n- Counterexample found → `falsified` + attach `counterexample`\n- Timeout / resource limit → `unknown`\n\n### 4.2 Determinism\n- Each proof run is **reproducible** with `{seed, limits}`.\n- Identical input (CJON bytes) + same `seed/limits` → identical output.\n\n### 4.3 Resource & Loop Guard\n- **Fuel Limit:** `limit:{steps:int}` — default `10k`\n- **Time Limit:** `limit:{time:\"200ms\"}` — default\n- **Branching Limit:** restricts expansion factor\n- **Visited-Set:** loop detection by state hashing\n- **Watchdog:** terminates after N steps with no progress\n- **Halt Reason:** logged as `metric.halt_reason` (`E-TIME`, `E-FUEL`, `E-LOOP`)\n\n---\n\n## 5) Validation Rules\n1. `prove` without `goal` → `E004: missing-required-slot`\n2. `prove!` without `{rule|risk|conf}` → `E013: unsafe-commit`\n3. `conf ∈ [0,1]` and `metric.time` validated as `ms|s`\n4. `model.axioms` must be string array → else `E003`\n5. `badge` is system-assigned only — external override forbidden\n\n---\n\n## 6) CJON Schema\n`json\n{\n \"$schema\":\"http://json-schema.org/draft-07/schema#\",\n \"title\":\"AILO-L Action\",\n \"type\":\"object\",\n \"required\":[\"verb\",\"slots\"],\n \"properties\":{\n \"verb\":{\"enum\":[\"assert\",\"assume\",\"model\",\"derive\",\"prove\",\"check\"]},\n \"mood\":{\"enum\":[\"?\",\"!\",\".\"]},\n \"slots\":{\"type\":\"object\"},\n \"hint\":{\"type\":\"object\"}\n },\n \"additionalProperties\":false\n}\n`\n\n---\n\n## 7) TypeScript Interface\n`ts\nexport type Badge = 'unverified'|'proved'|'falsified'|'unknown';\n\nexport interface LogicSlotsBase {\n thm?: string;\n hyp?: any[];\n claim?: string;\n form?: string;\n goal?: string;\n model?: { axioms?: string[]; [k: string]: any };\n proof?: string;\n oblg?: string[];\n badge?: Badge;\n metric?: { time?: string; steps?: number; conf?: number; srm?: number; halt_reason?: string };\n assume?: any[];\n with?: { solver?: string; checker?: string; seed?: number };\n limit?: { time?: string; steps?: number; branch?: number };\n}\n\nexport interface AILOAction {\n verb: 'assert'|'assume'|'model'|'derive'|'prove'|string;\n mood?: '?'|'!'|'.';\n slots: LogicSlotsBase & Record<string, any>;\n hint?: Record<string, any>;\n}\n\nexport type ProveResult = {\n badge: Badge;\n conf?: number;\n oblg?: string[];\n counterexample?: any;\n metric?: LogicSlotsBase['metric'];\n trace?: any;\n};\n`\n\n---\n\n## 8) Example Usage\n\n### 8.1 Simple Natural-Language Assertion\n`\nassert{claim:\"All valid trades preserve total credits.\",\n src:[\"rep-44003\",\"rep-44004\"]}.\n`\n\n### 8.2 Model + Proof (Arithmetic)\n`\nmodel{model:{axioms:[\"(a - x) + (b + x) = a + b\",\n \"valid_trade(tx) -> seller>=amount\"]}}.\nassume{hyp:[\"valid_trade(tx)\"]}.\nprove{thm:\"trade.conservation\",\n goal:\"total(s_final)=total(s_initial)\",\n with:{solver:\"arith-v1\", seed:7},\n limit:{time:\"250ms\", steps:8000}}?\n`\nExample Output:\n`\nend{ref:\"trade.conservation\",\n badge:\"proved\", conf:0.98,\n metric:{time:\"41ms\", steps:172}}.\n`\n\n### 8.3 Liveness Check (Counterexample Extraction)\n`\nprove{thm:\"no-starvation\",\n goal:\"F(not starve(a))\",\n with:{checker:\"ltl-v1\", seed:11},\n limit:{time:\"5s\", steps:200000, branch:128}}?\n`\nPossible Output:\n`\nend{ref:\"no-starvation\", badge:\"falsified\",\n counterexample:{path_len:12, states_hash:\"a1b2...\"},\n metric:{time:\"1.9s\", steps:42011, halt_reason:\"found_counterexample\"}}.\n`\n\n---\n\n## 9) Weakness → Mitigation Summary\n| Potential Issue | Symptom | Mitigation |\n|------------------|----------|-------------|\n| Infinite exploration | Endless loops | Step/time/branch limits, visited-set, watchdog, halt_reason log |\n| Non-determinism | Inconsistent outputs | Mandatory `seed`, identical input = identical output |\n| Resource overuse | High CPU/memory | Branch cutoff, caching, step limit |\n| Overcomplexity | High entry barrier | `assert` usable alone; `prove` optional |\n| Proof credibility | Missing context | Enforced `model.axioms`, attach `trace` or `counterexample` |\n| Security risks | Unsafe proof commits | Safety rule enforcement for `prove!` with rule/risk/conf check |\n\n---\n\n## 10) Operational Guide (3-Line Quick Start)\n1. When in doubt, `assert{claim}.` to record a statement.\n2. When verification is needed, use sequence `model → assume → prove?`.\n3. If a loop or stall occurs, set `limit` properly, fix `seed`, and inspect `halt_reason`.\n\n---\n\n**AILO-L completes the AILO ecosystem with an optional layer of verifiable reasoning — mathematical structure without rigidity, creativity without chaos.**"
